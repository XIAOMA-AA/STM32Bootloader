## 串口中文乱码排查
- 现象：串口助手中文乱码（涓枃娴嬭瘯），英文正常 → 非波特率问题（9600 正确）。
- 根因：源码（含 app_bootloader.c）为 UTF-8 编码，中文串按 UTF-8 字节发出；PC 串口助手默认按 GBK 解码 → 失败。
- 结论：**代码用 UTF-8 编写（已是），无需改固件**；把串口助手的接收编码改成 UTF-8 即可正常显示。GBK 仅当工具不支持 UTF-8 时的妥协方案，不推荐（破坏跨平台/Git 可读性）。

## push 到 GitHub 失败排查（443 超时 + 认证）
- 现象：SourceTree push 报 `Failed to connect to github.com port 443 ... Could not connect to server`，疑似网络问题。
- 根因1（网络）：本机 git/SourceTree 未走代理，裸连 GitHub 443 超时（中国大陆环境）。本机有本地代理客户端监听 `127.0.0.1:7897`（环境变量 https_proxy 指向它，沙箱可经此连通 GitHub）。
- 已修复：给本仓库（仅 local，不动全局）配置 `git config --local http.proxy/https.proxy http://127.0.0.1:7897`，`git ls-remote` 验证可连通。注意该代理客户端需保持运行，否则仍会 443 超时。
- 根因2（认证）：HTTPS 走 GitHub 需凭据，但本机无缓存凭据，且 GitHub 已禁用账号密码登录，必须用 Personal Access Token（PAT，scope=repo）。因在 SourceTree 中执行、terminal prompts disabled，无法在沙箱内交互输入。
- 处置：建议用户在 SourceTree 重新 Push，会弹出登录框，填 GitHub 用户名 + PAT 即可。可选：切 SSH（remote 改 git@github.com:XIAOMA-AA/STM32Bootloader.git）免 token；或配 credential.helper store 记住凭据。未代用户执行推送（涉及密钥，由用户自行完成）。
